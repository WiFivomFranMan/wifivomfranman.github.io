Keyboard editing for curve plot points, and a nav tree fix for def-library calibrations that nest tables more than two levels deep.

Keyboard editing for curve plot points

Editing a curve breakpoint used to mean a mouse drag, full stop. Click a point in the plot to select it — the marker grows to show it's active — and now the keyboard does the rest:

  • Up / Down nudge the point's value by the smallest storage step.
  • Left / Right move the point's breakpoint along the x axis, by the same smallest step.
  • Shift held with any of those takes a bigger, 10-step jump.
  • Ctrl (Cmd on Mac) + Left / Right move the selection itself to the previous or next point, with no mouse click needed.

Moving a breakpoint is deliberately conservative

A curve's breakpoints have to stay in ascending order — the interpolation math, and almost certainly the ECU's own lookup routine, both assume it. Letting a breakpoint nudge past or land on top of a neighboring point wouldn't just look odd on screen, it would silently change what the curve means. So an x nudge is clamped to stop one storage count short of whichever neighbor it's approaching, every time, rather than trusting the user not to overshoot.

Nav tree: def-library cals with deep table groups

Some factory calibrations organize their tables three or four levels deep (for example, Boost Control → WG Control → T1 WG Control → T1 WGDC Lookup). The nav tree was only ever built for two levels, so anything nested deeper collapsed into one very long, very flat list of top-level categories — one calibration showed 72 of them where 7 or 8 was the intended shape.

The tree now nests as deep as a calibration actually declares. This also folds a couple of duplicate spellings the def library had accumulated for the same bucket (Utility and Aux Functions meaning the same thing, plus a couple of literal typos) so they render as one category instead of two.

Housekeeping

Fixed a small, newly-exposed bug alongside the breakpoint work: the changed-value list's “was …” caption was always built from the old value, even on a row that changed only because its breakpoint moved — which read as a value edit that never happened. It only became possible to see once a breakpoint could move on its own.

Verified on the machine that built it: formatting, lints, the full workspace test suite (24 suites, 339 tests), the interface-glyph check, and a signed release build driven by hand — clicking a point, nudging it in all four directions, reselecting with Ctrl+arrow, and pushing a breakpoint hard against its neighbor to confirm the clamp holds rather than crossing it.
