Spool 26.2.0

Spool now tells you which table map a calibration is using — and lets you switch when there is more than one.

Download for Windows

Windows only. There is no macOS build for 26.2.0 yet; Mac users should stay on 26.1.0 until a signed DMG is published.
Windows is self-signed, so SmartScreen warns on first run: choose More info → Run anyway.

Which table map am I looking at?

Spool finds a calibration's table definitions in one of four places, and until now it picked the first one silently. The header now says which:

  • Template: mycal.tbl — a definition file sitting next to the bin
  • Factory def · 85_22_t1_118_DC_IC — the library built into Spool
  • Factory def (unverified) · ... — a close match Spool offered and you accepted, which has not been checked against your bin

Switching between them

When a bin has a definition file beside it and Spool's built-in library also recognises it, the header adds · factory def available. Click that — or use File → Reload using factory def — to reopen the calibration against the other map. The same works in reverse.

Why this matters

A definition file next to the bin has always quietly won over Spool's built-in library. If the two disagreed, you saw the older one and had no way to tell, because the table tree looks identical either way.

This caught us during the 1985 Turbo I definition work: 165 freshly corrected table names simply did not appear, because the bin was opened from a folder that had an older .tbl beside it. Confirming it meant copying the bin somewhere empty.

Neither one is treated as "correct"

Spool does not recommend one over the other, because the built-in library is not reliably the better answer — some hand-written definition files are more accurate, yours may carry corrections the shipped library does not have, and it may simply be newer. Both are offered; the choice is yours.

Switching reopens the file

The two maps can disagree about where tables live, not just what they are called, so Spool reopens the calibration rather than swapping the map underneath it. Unsaved edits are confirmed before being discarded, and a loaded comparison is closed — it was opened against the old map, so comparing across a switch would be meaningless. The option is unavailable while a project is open, since a project carries its own definitions.

Everything in this build was verified on the machine that built it: formatting, lints, the full test suite, the interface-glyph check, and a release build driven through the switch by hand on a real calibration.
